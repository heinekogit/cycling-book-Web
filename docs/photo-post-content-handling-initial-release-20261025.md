# 6-4 写真・投稿コンテンツの取扱方針（2026-10-25 実装照合）

## 判定

**撮影・保存・同期・公開の現行経路を整理し、写真ごとの公開・非公開選択と、公開用画像からのEXIF等の除去を初回公開の要件とした。6-4は実装・検証待ち。** 本書はプライバシーポリシーや投稿規約の確定版ではない。保存期間、削除時のDBとStorageの整合、問い合わせ・削除依頼への対応は6-6/6-7と合わせる。

## 現行のデータの流れ

| 場面 | 現行実装 | 利用者に説明すべき点 |
| --- | --- | --- |
| iOS実走中の撮影 | 撮影写真をアプリ専用領域に原画像と幅480pxのサムネイルで保存し、その時点の走行位置・時刻を写真データに記録。写真は1枚20MiB以下。 | 撮影直後のアプリ内保存は、走行終了後のSupabase同期とは別。同期前のデータは端末故障・アプリ削除などで失われ得る。端末の写真アプリには初期設定では保存されない。 |
| 任意の端末写真ライブラリ保存 | 設定「端末の写真ライブラリにも保存する」は初期値オフ。利用者がオンにすると写真追加の許可を求め、以後の実走中の撮影直後に写真アプリへ追加する。 | 写真アプリ側のコピーは走行終了・同期の成否に依存しない。アプリ内の走行やサーバー写真を消しても、端末写真アプリのコピーを自動では消さない。 |
| 実走の終了・同期 | 原画像とサムネイルをSupabase Storageの非公開`route-photos`バケットへ送り、`run_photos`へ撮影時刻・緯度経度などを記録。同期失敗時は端末内で再試行待ち。成功後はアプリ専用領域の写真ファイルを削除。 | 実走ログ・実走写真は自動公開されない。端末写真アプリへの保存は本人が設定した場合のみ。iOSの「共有」操作は本人が選んだ1枚をOSの共有画面へ渡す操作。 |
| Webルート編集での写真追加 | 所有者が既存の画像をマーカーへ選んで保存。JPEG・PNG・WebP・GIF・AVIFを受け付け、1枚20MiB以下。選んだファイルを原形式のままStorageへアップロードし、マーカー座標・コメント・撮影日時をDBへ記録。 | Webの選択ファイルは自動縮小・メタデータ除去をしていない。写真中の顔、住所、表札、車のナンバー、画像メタデータなどを公開前に確認する必要がある。 |
| ルート公開 | ルートを利用者が公開すると、公開対象のマーカーコメントと写真を匿名閲覧できる。現行の500m除外がオンなら範囲内のマーカー・写真を非表示にし、オフならホーム付近も含めて公開。 | 実走写真をルートへ選んだ場合や、マーカーに追加した写真は公開対象になり得る。公開プレビューで位置と写真を確認する。500m除外は写真の写り込みやメタデータを安全にする機能ではない。 |
| iOSの既存写真選択 | 実走画面の「開発用：写真ライブラリから選択」は20MiB境界試験のため`__DEV__`で限定。 | 初回公開の製品機能ではない。既存写真を実走やルートへ取り込む使い方は別途設計する。 |

根拠: iOSの`src/lib/{ride-photo-capture,device-photo-library,ride-sync,ride-storage,route-photos}.ts`、`src/app/(app)/{settings,ride,runs/[id]}.tsx`。Webの`src/features/routes/{markers,editor-api,api}.ts`、`src/pages/{RouteEditorPage,RouteDetailPage,RoutePhotosPage}.tsx`、`supabase/migrations/20261025000100_initial_free_limits.sql`。開発Webの公開プレビュー・匿名アクセス・写真除外・実機表示試験は`web-functional-smoke-test-20261018.md`、iPhoneの通常サイズ／20MiB前後の同期は`free-plan-initial-release-scope-20261025.md`に記録済み。

## 利用者向け説明の草案

> 走行中に撮影した写真は、まずCycling Bookのアプリ専用領域に保存されます。走行を保存すると、元画像と表示用の小さい画像をアカウントに紐付けてサーバーへ同期します。通信できない場合は再試行します。実走写真は自動では公開されません。
>
> 「端末の写真ライブラリにも保存する」は初期値オフです。オンにすると以後の撮影写真を撮影直後に端末の写真アプリにも追加します。このコピーは走行の同期とは独立しており、Cycling Bookのデータを削除しても写真アプリからは自動で削除されません。
>
> 【現行動作】ルートを公開すると、500m除外の対象外にあるマーカーの写真も他の人から閲覧できます。公開前に写真の内容、写り込んだ個人情報、位置を確認してください。ホーム地点から500m以内の除外は初期値オンですが、オフにするとその範囲の写真も公開されます。公開写真の画像メタデータの扱いは公開前に確定し、この説明へ追記します。

実装後の公開画面では、写真ごとに公開・非公開を選べることを説明する。上記の現行動作をそのまま初回公開時の説明文として使わない。

「投稿」は現行では本人が所有するルートのマーカーコメント・写真が中心で、第三者が公開ルートへコメントや写真を投稿する機能は確認できない。利用者が他人の権利やプライバシーを侵害する内容を載せないための規約、公開後の削除依頼・問い合わせ窓口は6-1/6-7で決める。

## 公開前に解く課題

1. **公開写真の画像メタデータ:** 利用者の方針は、元画像は非公開で保持し、公開用の別画像からEXIF等の不要なメタデータを除去すること。Webは選択した元ファイルをそのままアップロードし、iOSも原画像を保存・同期する。`exif: false`という撮影オプションだけを根拠に、保存済み画像からEXIFが除去されたとは断言しない。ルート表示に必要な位置はDBのマーカー座標で管理する。公開ページ・画像URL・共有時に公開用画像のみを配信し、元画像へ匿名または他ユーザーが到達できないように実装・試験する。[OWASPの画像アップロード指針](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)は画像の再処理と不要なメタデータの除去を推奨する。
2. **写真ごとの公開・非公開:** 利用者の方針は、ルート全体の公開とは別に写真ごとに公開・非公開を選ぶこと。現行は500m除外外のマーカー写真がルートとともに公開されるため、DB・Storageアクセス制御・Web編集画面・公開プレビュー・匿名閲覧に変更が必要。新規写真は非公開を初期値とすることを推奨し、利用者が公開を明示した写真のみを公開する。500m除外がオンのときは、公開を選んだ写真も圏内では非表示にする。既存公開ルートの写真をどう移行するかを決め、所有者／他ユーザー／匿名で公開・非公開・500m除外を試験する。実装前に6-4を完了扱いにしない。
3. **データ削除の実態:** Webで個別マーカー写真を消す時はStorageオブジェクトも削除しようとする。一方、実走・ルート全体の削除はDB行の削除が中心で、Storageオブジェクトの消去までは現行コードから保証できない。写真アプリのコピーも別管理。削除完了と表示する範囲を6-6で定義し、残存オブジェクトの処理を実装・試験する。
4. **公開文書と審査情報:** 写真と位置情報の利用目的、公開範囲、保存・削除、連絡先を利用規約・プライバシーポリシー・App Store申告へ一致させる。Webの公開用プレビュー、匿名閲覧、端末写真アプリ保存、iOS共有画面を公開候補で再確認する。

写真に写る顔や画像の位置情報が個人の識別につながり得る点は[個人情報保護委員会の注意喚起](https://www.ppc.go.jp/campaign/paw/?keyword=%22twitter%22)を参照。App Storeではアップロード可能な写真・動画等のデータ種別を申告対象として確認する必要があるため、[AppleのApp Privacy Details](https://developer.apple.com/app-store/app-privacy-details/)に沿って最終申告を作る。本書だけで法令・審査への適合を確定したものではない。
