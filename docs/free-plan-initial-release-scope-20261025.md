# 5-4 無料プランの提供範囲（2026-10-25 棚卸し）

5-1で決めた初回公開の対象は個人アカウントである。この文書は、現行の実装・開発DB設定と、初回公開の無料プランとして決めるべき範囲を分けて記録する。`free`という契約行があることと、機能・件数制限が強制されていることは別である。

## 現在の実装と強制状況

| 項目 | 現状 | 5-4での意味 |
| --- | --- | --- |
| 契約 | Auth登録時に個人アカウント、`active/owner`所属、`free/active`契約を作る。2026-10-25の開発DB照合で既存利用者の欠落は各0件。 | 無料契約の付与基盤は稼働。 |
| プラン定義 | 開発DBの`plans.features`は`free: {"max_public_routes":20}`、`pro: {"embed":true,"max_public_routes":1000}`、`group: {}`。`plan_entitlements`は3プランとも0行。 | 20件と1000件は**保存済み設定値であり、現行の強制上限ではない**。有料・グループ機能の提供を示すものでもない。 |
| Web | 個人のルート描画・編集・保存、GPX取込、マーカー写真、公開・非公開、プライバシー除外、マイページの実走表示を提供。`AccountProvider`は権利データを取得するが、`hasFeature()`/`getLimit()`は機能画面から呼ばれない。公開ルート一覧の10件取得は表示件数であり個人上限ではない。 | Webの作成・公開・写真アップロードはプラン別の件数・容量で止まらない。 |
| iOS | 保存済みルートの閲覧・追従、GPS走行記録、写真撮影、走行・写真同期を提供。同期は`users.account_id`を使い、契約や権利テーブルを参照しない。撮影時は元画像と幅480pxのサムネイルを保存。 | iOSからの走行・写真登録にもプラン別上限はない。Webで画面だけを制限しても足りない。 |
| DB・Storage | 個人の所有・公開範囲をRLSで制限するが、ルート件数、写真枚数、容量を`free`契約に応じて検査しない。開発DBの`route-photos`バケットは非公開で、個別の`file_size_limit`と`allowed_mime_types`はどちらもNULL。 | アップロード上限を決めるなら、少なくともStorage側のファイル単位制限と、Web/iOSの表示・エラー処理を揃える必要がある。 |

開発DBの写真オブジェクトは確認時点で3件、合計2,817,890バイト、最大2,776,404バイト。これはテストデータの規模であり、公開後の容量予測ではない。[Supabaseの公式資料](https://supabase.com/docs/guides/storage/uploads/file-limits)では、Freeプロジェクトのグローバルな単一ファイル上限は最大50MBで、バケット別にさらに小さく設定できる。[Storageの料金資料](https://supabase.com/docs/guides/storage/pricing)ではFree枠のファイル保存容量を1GBとしている。**サービス側の無料枠は、利用者ごとの無料プラン上限ではない。** 料金・枠は公開前に再確認する。

根拠: `supabase/baseline/003_initial_data.sql`、`src/features/accounts/{api,AccountProvider,entitlements}.ts(x)`、`src/features/routes/{api,editor-api,markers}.ts`、`src/features/gpx/api.ts`、iOSの`src/lib/{ride-sync,ride-photo-capture,saved-routes}.ts`、2026-10-25の開発DB読み取り照合。iOSリポジトリは読み取りのみで変更していない。

## 初回公開方針の提案（未確定）

個人向けに現在動いている機能を一つの無料プランとして提供し、課金導線、Pro専用機能、グループ機能は初回公開に含めない。これなら未実装の権利判定を公開画面に見せずに済む。`free`契約は本人の利用資格として扱い、現時点の`pro`/`group`定義を利用者向けの約束として表示しない。

件数・容量は別の決定が必要である。特に`max_public_routes:20`を正式な上限に採用するなら、Web・iOSの両方から迂回できないDB側で公開切替を止め、既存20件到達時の画面表示と境界試験を用意する。公開ルートだけを数えるのか、非公開ルートや走行から作ったルートも含めるのかを明文化する。写真はファイル単位の最大サイズ・許可形式をStorageで揃え、必要ならアカウント単位の総量・枚数を別途設計する。ファイルサイズだけでは総容量を抑えられない。

| 決めること | 現状 | 公開前に必要な判断 |
| --- | --- | --- |
| 現行の個人機能をすべて無料にするか | プランゲートなしで利用可能 | 無料範囲と、初回公開では課金しないことを確定する。 |
| 公開ルート件数 | `20`の設定値だけあり未強制 | 20件を採用するか、上限を設けないか。採用時はDB境界と既存データの扱いを決める。 |
| 非公開ルート・走行記録 | 上限なし | 数値上限を設ける場合はiOSのオフライン記録・再同期との整合が必要。 |
| 写真 | バケット個別上限なし | ファイル単位のサイズ・形式、総量または枚数制限の要否、超過時の表示を決める。 |
| 地図・Storageの費用 | プロバイダーの枠と利用量に依存 | 想定利用者数・監視・予算を4-7/4-9と合わせ、上限が必要な根拠を確認する。 |

**判定:** 5-4の現状棚卸しは完了。無料で提供する機能と数値上限は未確定で、上限のDB/Storage強制・Web/iOS表示も未実装。したがって進捗表では「作業中」を維持する。本番環境と開発DBへの設定変更は行っていない。
