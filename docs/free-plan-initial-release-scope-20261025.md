# 5-4 無料プランの提供範囲（2026-10-25 棚卸し）

5-1で決めた初回公開の対象は個人アカウントである。この文書は、現行の実装・開発DB設定と、初回公開の無料プランとして決めるべき範囲を分けて記録する。`free`という契約行があることと、機能・件数制限が強制されていることは別である。

## 現在の実装と強制状況

| 項目 | 現状 | 5-4での意味 |
| --- | --- | --- |
| 契約 | Auth登録時に個人アカウント、`active/owner`所属、`free/active`契約を作る。2026-10-25の開発DB照合で既存利用者の欠落は各0件。 | 無料契約の付与基盤は稼働。 |
| プラン定義 | 開発DBの`plans.features`は`free: {"max_public_routes":20}`、`pro: {"embed":true,"max_public_routes":1000}`、`group: {}`。`plan_entitlements`は3プランとも0行。 | 20件と1000件は**保存済み設定値であり、現行の強制上限ではない**。有料・グループ機能の提供を示すものでもない。 |
| Web | 個人のルート描画・編集・保存、GPX取込、マーカー写真、公開・非公開、プライバシー除外、マイページの実走表示を提供。`AccountProvider`は権利データを取得するが、`hasFeature()`/`getLimit()`は機能画面から呼ばれない。公開ルート一覧の10件取得は表示件数であり個人上限ではない。GPX入力は20MB、マーカー写真入力は1枚10MBまでの画面側チェックがある。 | Webの作成・公開はプラン別件数で止まらない。GPX・写真の入力チェックは、DB/StorageやiOSを含む共通上限ではない。 |
| iOS | 保存済みルートの閲覧・追従、GPS走行記録、写真撮影、走行・写真同期を提供。同期は`users.account_id`を使い、契約や権利テーブルを参照しない。撮影時は元画像と幅480pxのサムネイルを保存。 | iOSからの走行・写真登録にもプラン別上限はない。Webで画面だけを制限しても足りない。 |
| DB・Storage | 個人の所有・公開範囲をRLSで制限するが、ルート件数、写真枚数、容量を`free`契約に応じて検査しない。開発DBの`route-photos`バケットは非公開で、個別の`file_size_limit`と`allowed_mime_types`はどちらもNULL。 | アップロード上限を決めるなら、少なくともStorage側のファイル単位制限と、Web/iOSの表示・エラー処理を揃える必要がある。 |

開発DBの写真オブジェクトは確認時点で3件、合計2,817,890バイト、最大2,776,404バイト。これはテストデータの規模であり、公開後の容量予測ではない。[Supabaseの公式資料](https://supabase.com/docs/guides/storage/uploads/file-limits)では、Freeプロジェクトのグローバルな単一ファイル上限は最大50MBで、バケット別にさらに小さく設定できる。[Storageの料金資料](https://supabase.com/docs/guides/storage/pricing)ではFree枠のファイル保存容量を1GBとしている。**サービス側の無料枠は、利用者ごとの無料プラン上限ではない。** 料金・枠は公開前に再確認する。

根拠: `supabase/baseline/003_initial_data.sql`、`src/features/accounts/{api,AccountProvider,entitlements}.ts(x)`、`src/features/routes/{api,editor-api,markers}.ts`、`src/features/gpx/api.ts`、iOSの`src/lib/{ride-sync,ride-photo-capture,saved-routes}.ts`、2026-10-25の開発DB読み取り照合。

## 初回公開で確定した機能範囲

ユーザー確認により、**個人向けに現在動いている機能をすべて無料で提供する**と決めた。課金導線、Pro専用機能、グループ機能は初回公開に含めない。`free`契約は本人の利用資格として扱い、現時点の`pro`/`group`定義を利用者向けの約束として表示しない。Webのルート作成・編集・GPX取込・写真・公開、iOSのルート閲覧・追従・GPS走行・写真同期を、有料プランに分けない。

## 2026-10-25に確定した無料枠

- 個人の無料アカウントは公開ルートを最大20件まで持てる。非公開ルートと走行記録はこの件数に含めず、現時点では件数上限を設けない。20件到達後は既存ルートを非公開にすれば別のルートを公開できる。
- 写真は1ファイル20MB以下、画像形式のみ。開発DBの`route-photos`バケットではJPEG、PNG、WebP、GIF、AVIF、HEIC、HEIFを許可する。Webの入力はJPEG、PNG、WebP、GIF、AVIFに対応し、HEIC/HEIFはJPEG変換後の追加を案内する。iOS撮影では元画像の20MB超過を同期前に拒否する。
- 写真の**推奨**は長辺1600～2400px、JPEGまたはWebPで1枚1～3MB程度。20MBは推奨サイズではなく上限。iOSのサムネイルは従来どおり幅480px。画像の自動縮小・再圧縮は今回追加していない。
- 写真の枚数・アカウントごとの累計容量に上限はまだない。利用量の監視と必要に応じた総量制限は4-9で扱う。公開ルートの上限は個人の無料契約に適用し、グループ・Proの提供は初回公開対象外とする。

開発DBに`supabase/migrations/20261025000100_initial_free_limits.sql`を適用した。公開ルートの作成・公開切替をDBトリガーで数え、同一アカウントの同時公開操作も直列化する。Web/iOSは21件目の拒否を説明する。`supabase/tests/free_plan_limits.sql`と同内容のロールバック付き試験を開発DBで実行し、20件作成、21件目拒否、非公開化後の再公開、写真バケットの20MB・形式設定を確認した。合成データはロールバック済み。開発WebはPages `19b6659`へ配布し、HTTPS・SPA・開発Supabase接続のチェックに合格。ログイン済みChromeで非公開の既存ルート編集画面を開き、マーカー写真欄の推奨サイズと20MB上限の表示を確認した。本番DB・本番サイトには未適用。iOSの実機での20MB超過試験と実際の20MB付近のアップロード試験は別途行う。

**当時の判定:** 5-4の提供範囲と数値上限は確定し、開発DBの強制とWeb/iOSのコード実装・静的テストは完了。開発Webへの配布と画面確認は完了。以後の進捗は下記に記録する。

## 2026-10-25 iPhone実機での写真20MB境界

iOS開発ビルドに限り、実走画面へ「開発用：写真ライブラリから選択」を追加した（iOSリポジトリ`b7b9617`）。カメラ撮影と同じローカル保存・20MiB判定・サムネイル生成・走行写真登録の処理を通す。公開ビルドでは`__DEV__`ガードによりボタンと選択処理を使えない。iOS側の型チェック、33件の既存テスト、変更ファイルのlintは通過した。
