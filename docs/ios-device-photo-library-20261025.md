# 実走写真を端末の写真ライブラリにも保存する（2026-10-25）

実走中の写真は、従来どおりアプリ専用領域に元画像とサムネイルを保存し、走行終了後に開発用Supabase Storageの`route-photos`と`run_photos`へ同期する。アプリ専用領域は写真アプリではなく、アプリを削除すると未同期の写真が失われ得る。

追加仕様: iOSアプリの「設定」に「端末の写真ライブラリにも保存する」を設け、初期値はオフ、端末に設定値を保持する。オンにする際は写真ライブラリへの**追加のみ**の権限を求める。オンの状態で実走写真を撮影すると、まず従来のアプリ内保存を済ませ、走行終了・Supabase同期を待たずに写真ライブラリへ元画像をコピーする。ライブラリへのコピーに失敗してもアプリ内の写真を保持し、失敗を画面で知らせる。既に撮影した写真への遡及適用はしない。Supabaseの構成は変更しない。

iOS開発リポジトリに`expo-media-library`と設定画面・撮影処理を追加。TypeScript、ESLint、既存33テスト、Expo設定のiOS追加権限文言を確認済み。既存のiOSネイティブ設定を一時領域へ保全したうえでExpoの再生成を実行し、既存設定を復元して写真ライブラリ追加権限だけを反映した。CocoaPodsに`ExpoMediaLibrary 57.0.5`を組み込み、シミュレータ・実機向けDebugビルドはともに成功。シミュレータでは設定初期値オフ、写真ライブラリへの追加だけを求めるOSダイアログ、許可後のオン状態保持を確認し、検証後オフへ戻した。

2026-10-25、iPhone実機に新しい開発ビルドをインストールして確認。設定の初期値はオフ。オンにするとiOSの「写真への追加」権限ダイアログが表示され、許可後にオンとなった。実走中にiPhone本体のカメラで1枚撮影すると、走行画面の「写真を撮る (1)」表示を確認。走行を一時停止し、**終了・保存やSupabase同期を行う前**に写真アプリを開いたところ、撮影画像（3024×4032、2.9 MB）があり、情報画面に「Cycling Book から保存」と表示された。アプリを再起動しても写真アプリ側の画像は残り、実走は一時停止中の下書きとして復元された。検証後、設定はオフへ戻した。

未確認: 権限拒否時の動作、通信なしでの撮影。テスト用の未保存走行（約0.02 km、写真1枚）は一時停止状態で端末に残っている。公開前にこれらと、通常の走行終了後のSupabase同期を別途確認する。検証中のMetroログには位置情報バックグラウンドタスクからの`SQLiteErrorException: database is locked`も出た。写真ライブラリ保存との因果関係は未確認のため、走行記録の別件として調査が必要。
