react化推進のメモ

（2026/8/22・開始時点）　===========================================================
導入済み：
- Vite + React + TypeScript
- React Router
- ESLint
- Supabase用の環境変数ひな型
- 基本的なディレクトリ・CSS
- npmパッケージ一式
- 開発サーバー起動済み：http://127.0.0.1:5173/



＜全体の段取り＞　====================================================================
1. 現行Web版を調査・整理
/Users/dev_tomo/Desktop/cy2を最新原本として、以下を整理します。
- 各HTMLの役割と画面遷移
- 共通ヘッダー、ナビゲーション、カードなど
- 各JavaScriptの依存関係
- Supabaseの認証・テーブル・Storage利用
- Leafletなど外部ライブラリ
- 新旧・試験用HTMLの区別
最初に「移植対象」「共通化対象」「廃止候補」の一覧を作ります。

2. React版の共通基盤を作る
現在の土台に以下を追加します。
- React RouterによるURL設計
- 共通レイアウト
- ヘッダー・ナビゲーション
- Supabaseクライアント
- ログイン状態の管理
- 色、余白、文字サイズなどの共通スタイル
- 共通のデータ型
- エラー・読み込み中の表示
想定URLは、たとえば次のようになります。
/login
/explore
/runs/:runId
/mypage
/profile
/routes/:routeId/edit

3. 最初にweb-explore.htmlを移植
最新の中心画面であるweb-explore.htmlから着手します。
進め方は次の順です。
1. 見た目だけReactで再現
2. ダミーデータで操作確認
3. 既存JavaScriptの処理を分解
4. Supabaseの実データへ接続
5. 地図・検索・絞り込みなどを接続
最初からHTML内のJavaScriptを丸ごとReactへ貼り付けるのではなく、表示・データ取得・操作を分離します。

4. 認証と画面遷移を移植
web-login.htmlを基に以下を作ります。
- ログイン
- ログアウト
- セッション復元
- 未ログイン時のリダイレクト
- Supabase認証エラー表示
ここまでで、React版が独立したWebサービスとして動くようになります。

5. 閲覧系画面を順番に移植
依存関係が少ない順に進めます。
1. web-explore.html
2. web-detail.html
3. web-mypage.html
4. web-profile.html
この段階で、探索→詳細→マイページという主要導線を完成させます。

6. 編集・投稿系画面を移植
続いて、状態管理が複雑な画面を移します。
- ルート編集
- 写真管理
- 詳細編集
- プロフィール編集
- 管理画面
保存処理は、既存Supabaseデータとの互換性を保ちながら移します。

7. 実走記録機能を判断
run.htmlやtrial-run.htmlは最後に扱います。
WebブラウザのGPSは、バックグラウンド記録に制約があります。そのため、次のどちらかを選びます。
- Webにも簡易的な走行記録を残す
- 実走記録はReact Nativeアプリに集約する
距離計算や走行データ形式は、React Native版から流用できます。

8. 旧版との比較・切り替え
各画面で以下を確認します。
- 表示内容
- スマートフォン／PC表示
- Supabaseの読み書き
- ログイン状態
- 地図操作
- 既存URLからの移行
- 更新・戻る操作
- エラー時の動作
React版が安定するまでcy2は変更せず、比較対象として残します。
